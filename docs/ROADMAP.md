# 产品方向与改进计划

定位：办公优先、过程可解释、结果可核对的桌宠助手。

以下逐项标明实现状态；未完成项仍是规划，现有功能以README和实际版本为准。

## 第一优先级：安装、独立开关与退出

1. **首次使用向导（1.2.0已实现）**：提供“选择官方程序 → 核对版本 → 连接状态 → 用户主动验证 → 选择任务”的可视流程。路径选择成功后保存配置，保留手动配置能力。不能用自动发送测试按键代替用户确认。
2. **补充与领取独立调度**：当前状态机优先给出领取动作；当余额足够领取且槽位连续就绪，而用户关闭自动领取时，界面会等待，补充可能无法继续到目标。应让关闭领取仅关闭领取动作，不阻塞用户开启的补充任务。
3. **可靠退出与升级**：曾观察到退出后旧进程继续占用启动文件。需要复现并检查UIA工作线程、消息循环与PowerShell运行空间的释放顺序；验收标准包括窗口/托盘退出后进程结束、EXE可正常替换。尚不能认定具体根因，不能仅隐藏窗口或强制重命名文件就视为修复。

## 第二优先级：有解释的办公避让

4. **状态区显示下一步**：例如“正在保护文字编辑 → 点输入框外恢复”“余额已达目标 → 等待箱子”“结果待确认 → 暂停发送”。把等待、暂停、异常与用户主动停止区分开。
5. **场景预设**：
   - 日常使用：依靠自然输入，仅在条件允许时领取。
   - 空闲补充：允许补充与领取，保留输入保护。
   - 只读观察：不发送按键、不领取。
   保存用户选择，但重启后是否开始运行仍由用户决定；不持久复用过期的F24验证结果。
6. **更易判断的槽位状态**：突出真实冷却、余额不足和按钮暂未暴露。没有新鲜官方界面数据时标为未知，不用本地估算伪装成官方倒计时。

## 第三优先级：可核对的运行结果

7. **本机事件记录**：区分“发起领取”“观察到余额扣除与槽位变化”“未能确认”。默认保存有限条数，不写入输入内容或把本机观察包装成服务端最终到账。
8. **会话目标**：支持本次确认领取若干箱或运行到指定时刻后停止；只在已观察到的结果基础上统计，并显示停止条件。
9. **问题诊断与脱敏导出**：一键检查路径、兼容性、权限、窗口和输入保护状态，导出前预览并遮盖本机路径及标识；保持明确的文件白名单。

## 验收重点

- 日常使用体验：中文输入、文本选择、拖拽、切换窗口及不同缩放比例。
- 正确性：两个开关的四种组合、领取未确认、余额自然变化和连接丢失。
- 生命周期：停止后不派发新动作，退出后不残留进程，更新不混入本机日志。
- 表述准确：规划与已实现分开，本机结果与服务端结果分开，不承诺零干扰或账号安全。

产品差异应体现在这些可验证的行为上；不将“其他项目一定没有某功能”作为未经验证的宣传，也不靠更换名称或界面来声称技术独创。
